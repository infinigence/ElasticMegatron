# Reshard strategy lists (generated)

Reshard sequences are no longer hand-written per scale/scenario. They are **generated** by
`tools/strategy_gen`, which knows the model-arch registry + a per-GPU memory model and emits a
feasible `(TP, PP, CP, EP, DP, world)` sequence (each entry an override-dict over the launch
`base`), a runnable launcher recipe, and a peak-GB summary table.

```bash
python3 -m tools.strategy_gen --model qwen3-30b --gpus 8 --gpu-mem 80 \
        --scenario rl_dp_resize --out examples/strategies/seq.json
# -> writes seq.json + prints the run recipe + a per-step ~peakGB / cpu-adam table
```

The emitted file is a **list of override-dicts**: `overrides[0]` is `{}` (strategy[0] == launch
config, enforced by ElasticMegatron's `check_consistency`); later entries override only the dims
that change. Keys = `ParallelStrategy` fields (`world_size`, `tensor_model_parallel_size`,
`pipeline_model_parallel_size`, `context_parallel_size`, `expert_model_parallel_size`,
`expert_tensor_parallel_size`, `num_distributed_optimizer_instances`, `sequence_parallel`).
`check_reshard` cycles the list every `ELASTIC_RESHARD_INTERVAL` iterations and wraps to strategy[0].
The generator filters every entry against the GPU-memory cap (loud-fails otherwise) and flags which
entries need cpu-adam.

## Registry labels (`--model`)

`llama2-medium` (~2B), `llama2-7b`, `llama2-13b` (dense, `run_dense.sh`); `moe-4b`, `moe-15b`,
`qwen3-30b` (Qwen3-MoE, `run_qwen3_30b.sh`). Or pass `--config <ModelArch.json>` for an arbitrary
arch.

## Scenarios (`--scenario`)

- `rl_dp_resize` — data-parallel resize (world 8↔4, all other dims fixed): the RL rollout /
  actor-scaling case. Always yields an 8→4 scale-down.
- `verify_sweep` — fixed-world TP/PP/CP/EP variety for correctness sweeps.

## Committed fixtures

Two sequences are committed so launchers / platform YAML can reference a stable path:
`moe_30b.json` (`qwen3-30b`, `rl_dp_resize`) and `precision/dense_no_tp.json` (`llama2-medium`,
`rl_dp_resize`; see `precision/README.md`). Both vary only `world_size` (8→4→back to base; DP
derives). For MoE sequences the generator additionally pins `expert_tensor_parallel_size: 1` on
every non-empty override — the runtime (`parallel_strategy.py`) only supports ETP==1 for MoE
resharding — so `moe_30b.json`'s world=4 step is `{"world_size": 4, "expert_tensor_parallel_size": 1}`.
They are **regenerated by the tool**, not hand-edited — `tests/test_strategy_fixtures_drift.py` pins
them to the generator output (asserts the 8→4 step, and the ETP=1 pin for the MoE fixture).
Regenerate after a generator/registry change with the kwargs in that test.

## Use

```bash
# 30B (cpu-adam mandatory), committed sequence:
ELASTIC_ENABLED=1 ELASTIC_RESHARD_INTERVAL=2 CPU_OFFLOAD=1 \
ELASTIC_STRATEGY_LIST_FILE=examples/strategies/moe_30b.json ./run_qwen3_30b.sh

# or generate + run a fresh sequence (recipe is printed by the generator):
python3 -m tools.strategy_gen --model llama2-13b --gpus 8 --gpu-mem 80 \
        --scenario rl_dp_resize --out examples/strategies/seq.json
ELASTIC_ENABLED=1 ELASTIC_RESHARD_INTERVAL=2 \
ELASTIC_STRATEGY_LIST_FILE=examples/strategies/seq.json ./run_dense.sh MODEL_SIZE=13 TP=2
```
